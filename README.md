# make-knowledge-cards

一个把文章变成知识卡片的 Agent Skill。给它一段粘贴的正文，或一个本地 `.md` / `.txt` 文件，它输出 5-8 张可独立复习的卡片：一张卡只讲一个知识点，四段结构，可直接背诵、可当自测题用。

纯规则型 Skill，不含脚本、不装依赖。

## 1. 解决什么问题

读完一篇长文，能记住的往往只有开头和结尾；把文中的表格、金句、结构抄成笔记，复习时仍然找不到"我到底该记住什么"。摘要也不解决问题——摘要按篇幅压缩，卡片按知识点拆分，前者适合快速浏览，后者适合反复回忆。

这个 Skill 处理的是后者：把一篇文章拆成若干互不重叠、每张只讲一件事的知识单元，并给每张配上原文自带的例子或一道自测题，让"读过"变成"能回忆"。

它同时解决另一类常见失败：让模型总结文章时，很容易顺手补上原文没有的数据、因果和建议。这里把"不编造"做成硬规则——每个数字、事实、例子都必须能回溯到原文，信息不够就少出卡片，而不是凑数。

## 2. 主要功能

- **多体裁处理**：科普说明、操作指南、观点评论、案例叙述、多主题合集，先判体裁再抽知识点。
- **知识点抽取与合并**：只保留"不掌握就不算读懂这篇文章"的内容，同一概念多处出现时合并成一张卡，卡片之间内容重合不超过一两句。
- **张数自适应**：常规 5-8 张；完整文章只够 4 个知识点时就出 4 张并注明原因；短清单或 300 字以内的碎片文本出 3-5 张，不扩写。
- **四段式卡片**：标题 + 核心知识（可直接背诵的结论句）+ 简明解释（机制/条件/因果）+ 例子或自测。
- **原文例子优先，自测题兜底**：原文有场景或数据演算就压缩复述；只有结论时改出一道需要应用判断的题，答案写在括号里，方便遮挡复习。
- **归属与条件保留**：作者个人观点写成"作者认为/文中推测"，原文的限定条件、单位、术语照原样带上。
- **输出到对话或文件**：默认直接在对话里输出 Markdown；要求存档时写 `<主题>-knowledge-cards.md`。

**不支持**（遇到会直接说明，不会硬做）：网页 URL 抓取、PDF 解析、Anki/CSV 导出、图形界面或网页版卡片。

## 3. 安装方法

把 `skills/make-knowledge-cards` 整个目录复制到你的 Agent 的 skills 目录，保持 `SKILL.md` 位于目录根部：

```powershell
# Windows（示例：Codex 的 skills 目录）
Copy-Item -Recurse "skills\make-knowledge-cards" "$HOME\.codex\skills\"
```

```bash
# macOS / Linux（改成你所用平台的 skills 目录）
cp -r skills/make-knowledge-cards ~/.codex/skills/
```

不同平台的 skills 目录位置不同（有的叫 `skills/`，有的叫 `.user_skills/`），本质要求只有一条：`make-knowledge-cards/` 放进该目录，里面是 `SKILL.md`。

不需要 `pip install`，不需要 Node，也没有要注册的 API。

## 4. 使用方法

用自然语言触发，或直接指向文件路径：

```
把这篇文章做成知识卡片
帮我把这份笔记提炼成复习卡
notes/咖啡因.md 整理成知识卡片
用 $make-knowledge-cards 把下面这段拆成卡片
```

- 输入方式一：在对话里直接粘贴正文。
- 输入方式二：给出本地 `.md` / `.txt` 的路径，Skill 会完整读完全文再出卡（长文分段续读，不只看开头）。
- 输出默认在对话里，可直接复制；说"存成文件"则写入项目目录，文件名形如 `咖啡因-knowledge-cards.md`。
- 卡片语言跟随原文，要求翻译或换语言时才切换。

## 5. 输入输出示例

**输入**（`backup.md`，节选）：

```markdown
# 用 3-2-1 规则给个人文件做备份

3-2-1 规则只要求三件事：保留 3 份数据副本，存放在 2 种不同的存储介质上，
其中 1 份放在异地。第一步是盘点……第二步是落地两份本地副本……
第三步是把第三份放到异地。最后一步最容易被跳过：每季度做一次恢复演练，
从备份里随机取几个文件还原并打开，确认能读。
```

**输出**（节选）：

```markdown
## 3-2-1 备份规则：5 张知识卡片

### 卡片 1：3-2-1 规则只要求记住三件事
- 核心知识：3 份副本、2 种介质、1 份异地，构成一条记得住的备份规则。
- 简明解释：多数人备份失败不是技术问题而是规则记不住；三条约束分别对应防误删、防介质故障、防本地灾害。
- 自测：为什么强调“2 种介质”？（答案：单块硬盘故障不会同时带走两份副本）

### 卡片 3：两份本地副本要落在不同介质
- 核心知识：本地两份副本一份留在电脑硬盘，一份用移动硬盘定期同步。
- 简明解释：两者属于不同介质，单块硬盘故障时不会同时损失；同步要定期做，不是一次性拷贝。
- 自测：两份副本都放在同一台电脑的不同文件夹，是否满足要求？（答案：不满足，同介质故障会一起丢失）

### 卡片 5：没验证过的备份不算备份
- 核心知识：每季度做一次恢复演练，随机取文件还原并打开确认可读。
- 简明解释：备份成功不等于可恢复，只有实际还原过才能确认文件完整、格式能打开。
- 自测：备份软件显示“同步成功”，能否说明数据可恢复？（答案：不能，需要实际还原验证）
```

信息不足时不会硬凑。同一 Skill 对一篇 350 字的观点文章只会出 4 张，并在开头写一行"原文信息只够 4 张，未凑数"。

## 开发时验证过的文章类型

| 类型 | 篇幅 | 结果 |
| --- | --- | --- |
| 科普说明（咖啡因代谢） | 约 600 字 | 5 张 |
| 操作指南（3-2-1 备份） | 约 350 字 | 5 张 |
| 观点评论（小团队与 KPI） | 约 350 字 | 4 张，注明"原文信息只够 4 张，未凑数" |
| 碎片清单（跑步提醒） | 约 200 字 | 4 张，两条相关提醒合并，不扩写 |
| 清单式长文（周报十条） | 约 400 字 | 8 张，十个要点合并到上限内 |

SKILL.md 的 frontmatter 通过 `quick_validate.py` 校验（`Skill is valid!`）。

## 设计取舍

- 不拆同一机制的多个参数（峰值时间、半衰期、剂量放一张卡），避免卡片碎成数据点。
- 例子必须带场景或算例，不能把核心知识换个说法当例子；原文只有结论时改出自测题。
- 自测题要能应用判断，答案不能是核心知识的照抄。
- 不做评价、不延伸建议，也不生成总括性总结。
